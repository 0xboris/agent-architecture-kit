TypeScript monorepo split

The admin web app and the API live in one repository. They share business rules as code, through packages/domain, and exchange data only over HTTP, through the contract in openapi.json.

What lives where

PartHoldsNever holds
packages/domainModel types and brands, parse functions such as parseNoteTitle, pure rules such as newestFirst, ResultPorts, use cases, I/O, packages
an app's domain/That app's ports and the rules only it needsAnything the other app imports
openapi.jsonThe wire contract: paths, request and response schemas, constraints such as maxLengthHand edits. ./check fails when it is stale
apps/web/screens/Pages that arrange the public UI of several slicesUse cases, data access, business decisions

How a note title is checked

  • The web form calls parseNoteTitle from packages/domain and shows "Enter a title." before anything is sent.
  • The web app's adapters/api sends POST /notes through the client generated from openapi.json.
  • The API's route validates the body with its Zod schema, and its use case calls the same parseNoteTitle. The API's answer decides.
  • The mobile app has no shared code. It gets the same limits from the spec's maxLength and relies on the API's 422.
